Debug the Classrooms feature end-to-end. A student currently cannot access a grade folder — trace and fix every point of failure across the full stack, from the database query through to the UI render. Do not add new features. Only find and fix what is broken.
Start with the student access flow and trace it in this order:
1. Database layer

Verify the student enrollment records exist and are correctly linked to both the grade folder and its subject subfolders
Check that the student's user ID is present in the enrollment table and that the foreign keys between students, grade folders, and subjects are valid and not null
Confirm that no row-level security policy, permission rule, or query filter is silently excluding the student from the classrooms query
Check for any missing or broken joins between the classrooms table, subjects table, and enrollments table that would cause a student's grade folders to return empty or undefined

2. API / backend layer

Trace the API call that fetches classrooms for a logged-in student — log the raw response and confirm it returns the correct grade folders and subjects for that student
Check that the endpoint is filtering by the correct student ID from the session — not a hardcoded ID, a missing parameter, or an unauthenticated request
Verify the response shape matches what the frontend expects — if the frontend expects gradeFolder.subjects and the API returns gradeFolder.children, that mismatch would cause a silent render failure
Check for any unhandled promise rejections, 401/403 auth errors, or 404s on the classrooms endpoint when called from a student session

3. Frontend / routing layer

Confirm the student sidebar renders the "My Classes" nav item and that it is wired to the correct route
Trace what happens when a student clicks a grade folder — check the route definition, the page component it loads, and whether the correct classroom ID is being passed as a route param
Check that the grade folder page component is not gated behind a teacher-only role check that silently redirects or returns null for student sessions
Verify that loading states, error boundaries, and empty state components are not masking the real error — temporarily log the raw data and error state to the UI during debugging
Check that the subject subfolders inside a grade folder render correctly for a student session — not just the top-level folder

4. Role and permission layer

Confirm the student role is explicitly permitted to read classrooms, grade folders, and subjects in any role-based access control layer (middleware, context, or policy file)
Check that the role is being read correctly from the session — if the session returns role: null or an unexpected value, every permission check downstream will fail
Verify that teacher-only actions (create, edit, delete) are correctly separated from student read access — a misconfigured permission guard could be blocking read access entirely

5. End-to-end smoke test after fixes

Log in as a student, navigate to My Classes, open a grade folder, open a subject subfolder, and confirm Assignments, Study Materials, Feed, and Grades tabs all load without errors
Repeat the same flow as a parent to confirm their Classes view is also intact
Confirm a teacher can still create, edit, and manage classrooms without any regressions
